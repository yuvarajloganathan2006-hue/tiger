# Contributing to TIGER

1. Open an issue describing the feature or defect.
2. Keep changes modular and add tests.
3. Do not add API keys, telemetry, private data, or binary model weights.
4. Preserve third-party licenses and attribution.
5. Add a security note for new tools, integrations, or model-routing behavior.
6. Run formatting, type checks and tests before opening a pull request.

Early project status: architectural and scaffold contributions are welcome. Avoid claiming incomplete capabilities as implemented.
